# Coding Agent Instructions - GitHub Copilot Responses VoiceLive

This sample is a **Microsoft Foundry hosted agent**. It uses the GitHub Copilot
SDK with the Responses protocol and a Foundry BYOK model to provide streamed,
voice-friendly output for VoiceLive scenarios. It runs in
[Foundry Agent Service](https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/hosted-agents),
which manages hosting, security, scaling, and observability.

## Deployment mode

- **Direct code deployment:** `codeConfiguration` declares the Python runtime and
  entry point. A Dockerfile is not required.

## Key files

- `azure.yaml` - `azd` manifest for the Foundry project, model deployment, hosted
  agent, environment variables, and deployment mode
- `src/github-copilot-responses-voicelive/main.py` - Copilot SDK integration and
  Responses protocol streaming handler
- `src/github-copilot-responses-voicelive/pyproject.toml` - direct Python runtime dependencies
- `src/github-copilot-responses-voicelive/uv.lock` - portable, fully resolved dependency graph
- `README.md` - prerequisites and supported local run, VoiceLive, test, and
  deployment paths

Do not commit `.vscode` launch or task files generated by the Foundry Toolkit.

## Dependency workflow

Follow `samples/python/hosted-agents/DEPENDENCY_POLICY.md`.

`pyproject.toml` declares direct dependencies and `uv.lock` pins the complete
direct and transitive runtime graph. Regenerate the lock when dependencies change.

Run the dependency-policy checker with `--resolve` before completing dependency
changes.

## Runtime logging

Use the standard `logging` module for hosted diagnostics. E2E log assertions
must target deliberate sample-owned events rather than framework wording.

## Development workflow

```bash
azd provision
azd ai agent run
azd ai agent invoke --local "What is two plus two?"
azd deploy
azd ai agent invoke "What is two plus two?"
azd down
```
