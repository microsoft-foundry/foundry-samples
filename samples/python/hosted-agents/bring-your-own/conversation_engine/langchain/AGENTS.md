# Coding Agent Instructions — Voice Live Bridge LangChain Python

This is a Microsoft Foundry hosted text agent that implements Voice Live Bridge Protocol `1.0`
over `voice_conversation_engine`. Voice Live owns the audio pipeline; this sample handles only typed text and
control events.

## Cross-language consistency

Keep echo behavior, protocol handling, tests, and documentation aligned across the three Python
variants and the matching .NET sample. Apply changes to both languages unless the requested scope
explicitly names only one implementation.

## Deployment mode

- Direct code deployment: `azure.yaml` declares Python 3.13 and `main.py` as the entry point.
- Keep the sample self-contained under this directory. Do not add sibling-path dependencies,
  private package feeds, local wheels, or generated `.vscode` files.

## Key files

- `azure.yaml` — Foundry project, hosted-agent metadata, and protocol declaration
- `src/voice-live-bridge-langchain-python/main.py` — server entry point
- `src/voice-live-bridge-langchain-python/voice_runtime.py` — SDK callbacks; user messages trigger a fixed thirty-word story stream
- `src/voice-live-bridge-langchain-python/response_coordinator.py` — interruptible response tasks and terminal sequencing
- `src/voice-live-bridge-langchain-python/state.py` — connection state, ID correlation, and caller-heard text
- `src/voice-live-bridge-langchain-python/pyproject.toml` and `uv.lock` — fully pinned runtime and development dependency graph
- `sample.yaml` — repository build-readiness validation

Do not commit `.vscode` launch or task files generated by the Foundry Toolkit.

## Dependency workflow

Follow `samples/python/hosted-agents/DEPENDENCY_POLICY.md`. Keep the runtime and development
dependencies in `pyproject.toml` and the complete graph in `uv.lock`. Run `uv lock` after
dependency changes, then the static and resolver-backed policy checks.

## Streaming customization

Keep `send_echo` accepting `AsyncIterable[str]`, consumed incrementally with `async for`.
Customers replace the asynchronous `stream_story` generator inside `on_user_message`.
Do not buffer the entire source before sending or block the receive loop.
Do not reintroduce LLM clients, framework adapters, model environment variables, or model deployments.
Keep only the SDK's required transitive telemetry/authentication packages.

## Runtime logging

Use the standard `logging` module for server diagnostics. Reserve `print()` for local CLI utilities
such as the smoke client, where stdout is the intended interface. Never log prompts, responses,
credentials, or bearer tokens.

## Development workflow

From an initialized agent project, use `azd provision`, `azd ai agent run`, and `azd deploy` for the
hosted-agent lifecycle. Do not use `azd ai agent invoke` for this sample because it does not produce
Voice Live Bridge WebSocket events; use `scripts/smoke_test.py` for the local protocol check.

## Protocol constraints

- Declare only `voice_conversation_engine:1.0.0` in the manifest and use `/voice_conversation_engine`.
  Omit deprecated `bridgeProtocolVersion` and `voiceLiveCompatible` metadata; legacy metadata-selected
  `invocations_ws` remains a service/SDK compatibility path, not a requirement for this sample.
- Use `user.barge_in` / the typed user-barge-in callback; preserve heard-text and cancellation behavior.
- The application explicitly sends `session.ready` or `session.rejected` and owns response IDs,
  response tasks, interruption/cancellation/timeout handling, and connection state.
- Simplifying `on_user_message` must not remove other protocol callbacks, response/input-ID
  correlation, caller-heard state, or cleanup. Keep the receive loop free to process interruptions.
- Protocol `1.0` supports text input only. Do not add DTMF, image input, history mutation, or
  hosted-agent handoff under this version.
