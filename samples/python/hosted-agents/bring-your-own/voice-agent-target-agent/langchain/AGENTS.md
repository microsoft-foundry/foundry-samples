# Coding Agent Instructions — Voice Live Bridge LangChain Python

This is a Microsoft Foundry hosted text agent that implements Voice Live Bridge Protocol `1.0`
over `invocations_ws`. Voice Live owns the audio pipeline; this sample handles only typed text and
control events.

## Deployment mode

- Direct code deployment: `azure.yaml` declares Python 3.13 and `main.py` as the entry point.
- Keep the sample self-contained under this directory. Do not add sibling-path dependencies,
  private package feeds, local wheels, or generated `.vscode` files.

## Key files

- `azure.yaml` — Foundry project, model, hosted-agent metadata, and protocol declaration
- `src/voice-live-bridge-langchain-python/main.py` — server entry point
- `src/voice-live-bridge-langchain-python/voice_runtime.py` — thin Bridge callbacks and command dispatch
- `src/voice-live-bridge-langchain-python/response_coordinator.py` — response execution, terminal
  sequencing, cancellation, and detached-task cleanup
- `src/voice-live-bridge-langchain-python/state.py` — bounded connection state and session store
- `src/voice-live-bridge-langchain-python/model_contract.py` — model backend protocol shared without
  circular imports
- `src/voice-live-bridge-langchain-python/langchain_agent.py` — LangChain tool loop and Foundry Responses adapter
- `src/voice-live-bridge-langchain-python/pyproject.toml` — runtime and development dependencies
- `src/voice-live-bridge-langchain-python/uv.lock` — fully pinned dependency graph
- `sample.yaml` — repository build-readiness validation

Do not commit `.vscode` launch or task files generated by the Foundry Toolkit.

## Dependency workflow

Follow `samples/python/hosted-agents/DEPENDENCY_POLICY.md`. Runtime and development
dependencies are declared in `pyproject.toml`; `uv.lock` is the portable, fully
pinned consumer artifact. Regenerate the lock whenever a dependency input changes,
and run the static and resolver-backed policy checks before completing dependency
changes.

## Runtime logging

Use the standard `logging` module for server diagnostics. Reserve `print()` for local CLI utilities
such as the smoke client, where stdout is the intended interface. Never log prompts, responses,
credentials, or bearer tokens.

## Development workflow

From an initialized agent project, use `azd provision`, `azd ai agent run`, and `azd deploy` for the
hosted-agent lifecycle. Do not use `azd ai agent invoke` for this sample because it does not produce
Voice Live Bridge WebSocket events; use `scripts/smoke_test.py` for the local protocol check.

## Protocol constraints

- Keep `bridgeProtocolVersion: "1.0"`, `voiceLiveCompatible: "true"`, and `invocations_ws` aligned.
- The application explicitly sends `session.ready` or `session.rejected` and owns response IDs,
  background tasks, cancellation, and conversation state.
- Protocol `1.0` supports text input only. Do not add DTMF, image input, history mutation, or
  hosted-agent handoff under this version.
