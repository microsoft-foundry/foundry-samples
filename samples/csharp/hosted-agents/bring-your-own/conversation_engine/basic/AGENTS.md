# Coding Agent Instructions — Voice Live Bridge Basic .NET

This is a Microsoft Foundry hosted text agent that implements Voice Live Bridge Protocol `1.0`
over `voice_conversation_engine`. Voice Live owns the audio pipeline; this sample handles only typed text and
control events. User messages trigger a fixed thirty-word story stream without an LLM client or history.

## Cross-language consistency

Keep echo behavior, protocol handling, tests, and documentation aligned across the three Python
variants and the matching .NET sample. Apply changes to both languages unless the requested scope
explicitly names only one implementation.

## Deployment mode

- Direct code deployment: `azure.yaml` declares .NET 10 and `VoiceLiveBridgeBasic.dll` as the entry
  point.
- Keep the sample self-contained under this directory. Do not add Docker artifacts, sibling-path
  dependencies, local packages, private feeds, or generated `.vscode` files.

## Key files

- `azure.yaml` — Foundry project, hosted-agent metadata, and protocol declaration
- `src/voice-live-bridge-basic-dotnet/Program.cs` — server entry point and dependency registration
- `src/voice-live-bridge-basic-dotnet/VoiceAgent.cs` — SDK callbacks; user messages trigger a fixed thirty-word story stream
- `src/voice-live-bridge-basic-dotnet/VoiceResponseCoordinator.cs` — interruptible response tasks and terminal sequencing
- `src/voice-live-bridge-basic-dotnet/VoiceConnectionState.cs` — connection state, ID correlation, and caller-heard text
- `src/voice-live-bridge-basic-dotnet/tests/` — deterministic unit tests and test doubles
- `src/voice-live-bridge-basic-dotnet/smoke/` — protocol-aware WebSocket smoke client
- `sample.yaml` — repository build-readiness validation

Do not commit `.vscode` launch or task files generated by the Foundry Toolkit.

## Dependencies and feeds

- Keep direct package versions explicit in each project file.
- All packages resolve only from nuget.org through the single-source `NuGet.config`.
- Use the `Azure.AI.AgentServer.Invocations` `1.0.0-beta.8` Voice API with public Core beta.30.
  Normal restore/deployment requires beta.8 publication on nuget.org; do not substitute beta.7.
- Do not add credentials, local NuGet packages, VCS dependencies, or private feeds.

## Streaming customization

Keep `SendEcho` accepting `IAsyncEnumerable<string>`, consumed incrementally with `await foreach`.
Customers replace the `StreamStory` async iterator inside `OnUserMessageAsync`.
Propagate cancellation using `[EnumeratorCancellation]` and `WithCancellation`.
Do not buffer the source, block the receive loop, or reintroduce model clients/configuration.

## Runtime logging

Use `ILogger` for server diagnostics. Reserve `Console.WriteLine` for the smoke client, where stdout
is the intended interface. Never log prompts, responses, credentials, API keys, or bearer tokens.

## Development workflow

From an initialized agent project, use `azd provision`, `azd ai agent run`, and `azd deploy` for the
hosted-agent lifecycle. Do not use `azd ai agent invoke` or Agent Inspector as protocol tests because
they do not produce Voice Live Bridge WebSocket events; run the smoke client instead.

Restore, build, format, and test from the sample root using the commands in `sample.yaml`.

## Protocol constraints

- Declare only `voice_conversation_engine:1.0.0` and use `/voice_conversation_engine`.
  Omit deprecated `bridgeProtocolVersion` and `voiceLiveCompatible` metadata; legacy metadata-selected
  `invocations_ws` remains a service/SDK compatibility path, not a requirement for this sample.
- Bridge Protocol `1.0` is the application protocol; `voice_conversation_engine` `1.0.0` is the Hosted Agent
  ingress transport version. Do not conflate them.
- Use `user.barge_in` / the typed user-barge-in callback; preserve heard-text and cancellation behavior.
- The application explicitly sends `session.ready` or `session.rejected` and owns response IDs,
  response tasks, interruption/cancellation/timeout handling, and connection state.
- Simplifying `OnUserMessageAsync` must not remove other protocol callbacks, response/input-ID
  correlation, caller-heard state, or cleanup. Keep the receive loop free to process interruptions.
- Protocol `1.0` supports text input only. Do not add DTMF, image input, history mutation, or
  hosted-agent handoff under this version.
